# Jarvis - 자기계발 보상 에이전트

목표를 입력하면 일정을 짜 주고, 과제를 끝낼 때마다 게임처럼 보상을 주는 개인용 CLI 에이전트입니다.

## 목적과 대상 사용자
- **대상:** 배우고 싶은 것은 많지만 계획 단계에서 생각으로만 끝나는 대학생 (개발자 본인 1명).
- **문제:** 의지만으로는 꾸준히 실행하기 어렵습니다.
- **해결:** 큰 목표를 하루 단위 과제로 쪼개 일정에 배치하고, 완료할 때마다 XP, 레벨, 연속 달성(streak), 랜덤 상자 보상을 줍니다. 달성률을 점검해 과제량도 조정하도록 제안합니다.
- **범위 밖:** 다중 사용자, 로그인, 모바일 앱, 푸시 알림, 외부 서비스 연동.

## 기능
1. **일정 분할 (`plan`)** - LLM이 목표를 난이도 1~3의 일일 과제로 나눕니다. 날짜 배치는 코드가 합니다.
2. **보스 스테이지** - 7일마다, 그리고 마지막 날에 총복습 모의고사 과제를 자동 배치합니다. 클리어하면 XP 100과 보너스 50포인트를 받습니다.
3. **보상** - 난이도별 XP, 레벨, streak 보너스(최대 7일). 50포인트로 랜덤 상자를 열면 일반/희귀/에픽/레전더리 등급의 치장 아이템(옷/바지/악세사리)이 나오고 부위별로 착용할 수 있습니다. 확률은 60/25/12/3%입니다.
4. **점검 (`report`)** - 달성률, 난이도별 완료율, 자주 못 한 요일, 과제량 조정 제안(40% 미만 줄이기, 90% 이상 올리기)을 보여 줍니다. 제안만 하고 자동으로 바꾸지는 않습니다.

## 실행 방법
Python 3.11 이상이 필요합니다.
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # OPENROUTER_API_KEY 입력 (.env는 git에 올라가지 않음)

python -m jarvis.cli plan "파이썬 기초 배우기" --days 7
python -m jarvis.cli today
python -m jarvis.cli done 2
python -m jarvis.cli status
python -m jarvis.cli open-box
python -m jarvis.cli inventory
python -m jarvis.cli equip "털모자"
python -m jarvis.cli report
python -m pytest -q          # 테스트 65개
```
`plan` 외 명령은 API 키 없이 동작합니다. `add-goal`, `add-task`로 과제를 직접 넣을 수도 있습니다. 데이터는 `data/state.json`에 저장됩니다.

## 작업 과정
Claude Code에게 먼저 계획을 설명받고 확인한 뒤, 작은 단위로 구현하고 기능마다 커밋했습니다.
1. 보상 규칙(XP/레벨/streak)과 테스트 → 2. 랜덤 상자 → 3. 저장과 CLI → 4. LLM 일정 분할 → 5. OpenRouter로 전환 → 6. 보스 스테이지 → 7. 상자 CLI → 8. 리포트 → 9. 검증과 README.

## 검증 결과
**대표 사례** (실제 OpenRouter 호출, 7일 계획): 과제 7개와 보스 1개가 쉬운 것부터 배치됐습니다. 매일 완료하자 연속 7일, 레벨 1에서 2로 상승, 보스 클리어 보너스로 포인트 340을 얻었고, 상자에서 `[일반] 털모자`가 나와 인벤토리에 들어갔습니다. 리포트는 달성률 8/8(100%)과 "난이도를 올려 보세요"를 보여 줬습니다.

**엣지 케이스와 실패**

| 상황 | 결과 |
|---|---|
| 4일 쉬고 완료 | streak가 1로 초기화 |
| 같은 과제를 두 번 완료 | 거부, XP 중복 지급 없음 |
| 없는 과제 번호, 없는 아이템 착용 | 한글 오류 메시지, 데이터 변경 없음 |
| 포인트 50 미만으로 상자 열기 | 거부, 포인트 유지 |
| LLM이 JSON이 아닌 답을 줌 | 1회 재시도 후 오류 안내, 아무것도 저장 안 함 |
| API 키 없음 | 호출 없이 설정 방법 안내 |

## 효과적인 실천 방법 3가지
1. **계획 확인 후 작은 단위로 구현, 기능마다 커밋.** 방향이 어긋나면 일찍 바로잡을 수 있었습니다. 랜덤 상자와 보스 스테이지도 계획 단계에서 추가 요구를 반영했습니다.
2. **LLM에는 내용만, 계산은 코드로.** LLM이 날짜를 정하지 않아 날짜 오류가 없고, 보상과 streak는 순수 함수라 테스트하기 쉬웠습니다.
3. **LLM 호출을 함수로 주입해 가짜 응답으로 테스트하고, 실제 호출은 따로 한 번 확인.** 테스트가 빠르고 비용이 들지 않으며 응답 형식 오류도 재현할 수 있었습니다.

## 어려움 3가지
1. **비밀키 관리.** 예시 파일에 실제 키가 들어갈 뻔했습니다. 그 파일을 커밋에서 제외하고 키를 `.env`로 옮겼으며, 이후 커밋 전에 `sk-` 패턴을 자동 검사합니다. 또 키에 하이픈 대신 공백이 섞여 401이 났는데 형식을 점검해 고쳤습니다. *남은 문제:* 채팅에 노출된 키는 제출 후 교체해야 합니다.
2. **개발 환경.** WSL의 `git push`가 인증을 기다리며 멈췄고 `gh`도 없었습니다. `gh`를 설치해 로그인하고 자격 증명 도우미를 연결해 해결했습니다.
3. **LLM 응답의 불안정성.** 형식이 틀릴 수 있어 검증과 1회 재시도를 넣었습니다. *남은 문제:* 과제 내용의 질은 모델에 달려 있어 코드로 보장할 수 없습니다.

## 알려진 한계
- CLI만 제공하며 캐릭터 화면은 없습니다. 아이템은 이름 데이터뿐이고, 나중에 화면에서 치장할 수 있도록 부위별 착용 상태만 저장합니다.
- 완료한 날짜를 기록하지 않아 리포트는 "기한 기준"으로 집계합니다.
- 보스는 완료 체크만 하며 모의고사 점수는 반영하지 않습니다.
- 단일 사용자 전용이고 `data/state.json` 하나에 저장합니다.
- 제안(과제량 조정)은 자동 적용되지 않습니다.

## 채점용 핵심 소스 파일
1. `jarvis/rewards.py` - XP, 레벨, streak, 랜덤 상자
2. `jarvis/models.py` - 데이터 저장, 완료 처리, 인벤토리
3. `jarvis/planner.py` - LLM 일정 분할, 응답 검증, 보스 배치
4. `jarvis/review.py` - 달성률 리포트와 제안
5. `jarvis/cli.py` - 명령어 진입점

테스트는 `tests/`에 있습니다.
